Create `src/state_core/reactive.py` with a `ReactiveTrigger` class that:

1. **Constructor**: `__init__(self, scheduler: DAGScheduler, dag_provider: Callable[[], tuple[list[Node], list[Edge]]], watched_events: frozenset[str] | None = None)`
   - Stores scheduler ref, dag_provider, watched_events (default: `{"state.step.advanced", "state.slice.worktree_ready", "state.phase.planned"}`)
   - Uses `frozenset` for watched_events (immutable, hashable, thread-safe)

2. **`on_event(self, event_row: dict[str, Any]) -> None`** — sync callback compatible with `SqliteEventStore.add_post_commit_callback`.
   - Extracts `event_row.get("type")` safely (returns `None` for missing key).
   - If type is not in `self._watched`, returns immediately (no-op for non-watched events).
   - If type is watched, schedules `self._tick()` via `asyncio.create_task()` (must be called from within a running event loop context — same as `SseBus.on_event`).
   - NEVER awaits anything — this is a sync callback; the event store must not block on post-commit hooks.

3. **`async _tick(self) -> None`** — internal tick dispatcher.
   - Calls `self._dag_provider()` to get current `(nodes, edges)`.
   - Calls `await self._scheduler.tick(nodes, edges)`.
   - Wraps in try/except and logs (via `structlog`) without re-raising — a tick failure must not crash the post-commit path.

4. **`watched_events` property**: Returns the current `frozenset` of watched event types.

Follow the established patterns:
- `SseBus.on_event()` — sync callback → `asyncio.create_task()` → async method
- `StepExecutor` injection pattern — `Callable[[Node], Awaitable[None]]`
- `structlog.get_logger(__name__)` for logging (same as every other module)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| post-commit callback → tick dispatch | Event row data crosses from event store into scheduling logic — `event_row["type"]` is untrusted (can be any string) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-047-01 | Denial of Service | `ReactiveTrigger.on_event()` | mitigate | `on_event()` uses `.get("type")` with None fallback → non-watched types are no-ops. `_tick()` is wrapped in try/except (never re-raises). `asyncio.create_task()` is fire-and-forget — a slow tick does not block the event store's post-commit path. |
| T-047-02 | Tampering | `ReactiveTrigger._tick()` | mitigate | `dag_provider()` and `scheduler.tick()` are trusted callables injected at daemon startup. The trigger does not deserialize or interpret event data — only checks event type. |
| T-047-03 | Elevation of Privilege | mode boundary | accept | `ReactiveTrigger` lives in `src/state_core/` (kernel tier). No mode-specific logic. Tick dispatch does not cross mode boundaries — the scheduler is mode-agnostic. |
| T-047-04 | Information Disclosure | watched event types | accept | The set of watched event types (`frozenset`) is a compile-time constant with no secrets. Logging at info level emits event types only (no event data). |
</threat_model>
