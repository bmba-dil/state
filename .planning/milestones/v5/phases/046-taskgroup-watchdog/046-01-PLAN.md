### Step B: Add _inspect_for_cancelled() recursive inspector

Add this function above the `DAGScheduler` class:

```python
def _inspect_for_cancelled(exc: BaseException) -> None:
    """Recursively inspect exception group tree for swallowed CancelledError.

    Python's asyncio.TaskGroup can silently drop CancelledError from
    ExceptionGroup contents when other exceptions are present
    (CPython #116720). This inspector walks the entire exception group
    tree and raises SwallowedCancelledError if ANY CancelledError is
    found — failing loud instead of silently deadlocking the scheduler.

    Args:
        exc: The exception to inspect (may be a leaf exception or group).

    Raises:
        SwallowedCancelledError: If a CancelledError is found anywhere
            in the exception tree.
    """
    if isinstance(exc, asyncio.CancelledError):
        raise SwallowedCancelledError(
            "Watchdog detected swallowed CancelledError in "
            "asyncio.TaskGroup exception group"
        ) from exc
    if isinstance(exc, (ExceptionGroup, BaseExceptionGroup)):
        for sub_exc in exc.exceptions:
            _inspect_for_cancelled(sub_exc)
```

### Step D: Integrate watchdog into tick()

Wrap the TaskGroup block with exception handling:

```python
try:
    async with asyncio.TaskGroup() as tg:
        for _, slice_nodes in slice_entries:
            tg.create_task(_run_slice(slice_nodes))
except BaseExceptionGroup as eg:
    # P0-16 defence: inspect for swallowed CancelledError BEFORE re-raising
    _inspect_for_cancelled(eg)
    raise
```

**Why `except BaseExceptionGroup` (not `except*`):** We want to inspect the ENTIRE group at once before propagating. `except*` would split the group and only catch matching sub-exceptions, which could miss CancelledErrors embedded alongside other exception types.

**Why `BaseExceptionGroup` (not `ExceptionGroup`):** `CancelledError` is a `BaseException` (like `KeyboardInterrupt`), not an `Exception`. TaskGroups wrap exceptions in `BaseExceptionGroup` when `BaseException` subclasses are present. Catching only `ExceptionGroup` would miss groups containing `CancelledError`.

**Edge case — no exceptions:** When all tasks complete normally, the `except` block is not entered, and execution proceeds to `return dispatched` as before.

### Test 6: Nested TaskGroup — CancelledError swallowed by inner group
This is the core P0-16 regression scenario from CPython #116720.

- Setup step executor that internally uses an `asyncio.TaskGroup`:
  ```python
  async def inner_tg_executor(node: Node) -> None:
      async with asyncio.TaskGroup() as inner:
          inner.create_task(raise_cancelled())
      # If inner TaskGroup swallows CancelledError, execution reaches here
      raise ValueError("inner completed but cancelled was swallowed")
  
  async def raise_cancelled():
      raise asyncio.CancelledError()
  ```
- The inner TaskGroup's `__aexit__` should propagate the `CancelledError` in a `BaseExceptionGroup`. But due to CPython #116720, if there are other tasks/exceptions, the CancelledError may be silently dropped.
- The watchdog must detect this: if the outer tick() receives any exception, it inspects the group tree for CancelledError.

**Note:** Python 3.12 behavior may vary. If the inner TaskGroup properly propagates CancelledError (as a BaseExceptionGroup), the watchdog will catch it via the `except BaseExceptionGroup` in tick(). If the inner TaskGroup swallows it (the P0-16 scenario), the executor's subsequent `raise ValueError` creates an ExceptionGroup at the outer level — but the cancelled sibling tasks' CancelledErrors will still be in the outer group. The watchdog's recursive inspection will find them.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| step_executor → DAGScheduler.tick() | Untrusted step executor code raises arbitrary exceptions (including CancelledError) |
| TaskGroup.__aexit__ → _inspect_for_cancelled() | Exception groups from TaskGroup may contain crafted exception trees |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-046-01 | Denial of Service | `_inspect_for_cancelled()` | mitigate | Recursive exception group traversal is bounded — Python's ExceptionGroup nesting depth is naturally limited (< 100); no infinite recursion risk. Watchdog only reads exception attributes, never modifies exception state. |
| T-046-02 | Denial of Service | `SwallowedCancelledError` | mitigate | SwallowedCancelledError always chains the original CancelledError via `from exc` — the original exception is preserved for forensics. The watchdog never suppresses the original exception group; it re-raises via `raise` after inspection. |
| T-046-03 | Tampering | Step executor injecting crafted ExceptionGroup | accept | The step executor is injected by the caller (daemon or test) — it is a trusted component by construction. If a malicious step executor crafts fake exception groups, it can already cause arbitrary behavior without needing the watchdog. |
| T-046-04 | Elevation of Privilege | N/A | accept | Watchdog operates entirely within the scheduler's async context — no privilege boundaries crossed. |
</threat_model>
