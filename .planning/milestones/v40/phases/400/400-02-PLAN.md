Structure sections:
1. Overview: "Composite events propagate upward through the hierarchy. When all children

3. Slice → Stage Cascade: Trigger: state.slice.shipped. Check: all child Slices of parent
   Stage are `shipped`. Action: emit state.stage.slices_shipped. Transition: Stage
   in_progress → verified.
4. Stage → Arc Cascade: Trigger: state.stage.completed (Stage reaches shipped). Check:
   all child Stages of parent Arc are `shipped`. Action: emit state.arc.stages_shipped.
   Transition: Arc in_progress → auditing (D-18).
5. Projector Implementation pseudocode: each child terminal event triggers a check function;
   each composite event is a SEPARATE store.append() — no nested transactions; on daemon
   startup, projector rebuilds all STATE.md from event stream.
6. Composite State Computation (D-19) rules:
   - Stage "in_progress" = any child Slice has status ∈ {worktree_ready, in_progress}
   - Stage "verified" = all child Slices are `shipped` AND Stage itself is verified
   - Arc "in_progress" = any child Stage has status ∈ {in_progress, verified}
   - Arc "auditing" = all child Stages are `shipped` (D-18 guard)
   - Arc "shipped" = all child Stages are `shipped` AND Arc itself is shipped
   - "Any" vs "all" thresholds: "in_progress" uses ANY active child; terminal states use ALL children.
7. Edge Cases: What if Slice has 0 Steps? (treat as soft-done for cascade); What if Stage
   has 0 Slices? (treat as soft-done); What if Arc has 0 Stages? (treat as soft-done —
   can go directly to auditing).
