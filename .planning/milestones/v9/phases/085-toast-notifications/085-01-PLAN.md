<objective>
Create a toast notification handler for the `ui.toast` TUI feature. Subscribes to daemon SSE events via `api.event` bus — step ended (slice completion), step failed (gray-area/error), server connected (auth refresh) — maps each event to a domain toast message, applies de-duplication (same message within 10 seconds suppressed), and dispatches via `api.ui.toast()` with correct variant and duration per the design system's copywriting contract.

Purpose: Give the user ambient awareness of slice completions, drill availability, gray-area decisions, and auth state changes — surfaced as transient terminal toasts managed by opencode's native toast system. De-duplication prevents notification spam during rapid event bursts.

Output: One new source file (`toast.ts`), one test file (`toast.test.ts`), one modified file (`tui.ts` with `setupToast(api)` wiring).
</objective>

**DEBOUNCE_MS constant:**

**ToastEntry type:**
```typescript
interface ToastEntry {
```

**shouldSuppressToast(message: string, history: Map<string, number>, now?: number): boolean**
- If `now` is not provided, use `Date.now()`
- Check if `message` exists in `history` AND `(now - timestamp) < DEBOUNCE_MS`
- Returns `true` (suppress) if within window, `false` otherwise
- Pure function — does not mutate history

**recordToast(message: string, history: Map<string, number>, now?: number): void**
- If `now` is not provided, use `Date.now()`
- Sets `history.set(message, now)`
- Prunes stale entries: iterates history, deletes any entry where `(now - timestamp) >= DEBOUNCE_MS`
- Mutates the passed-in Map (not pure, but exported for test inspection)

**dispatchToast(api: TuiPluginApi, variant: TuiToast["variant"], message: string, duration?: number): void**
- Calls `shouldSuppressToast(message, TOAST_HISTORY)` — if suppressed, return early (no-op)
- Calls `recordToast(message, TOAST_HISTORY)` to record this toast
- Calls `api.ui.toast({ variant, message, duration })` to show the toast
- `duration` defaults: info/success → 4000, warning → 6000, error → 0 (persistent)

**toastMessageForStepEnded(event: EventSessionNextStepEnded): string**
- Format: `"Slice complete ✓"` (the ✓ is a separate character, joined by space)
- If `event.properties.sessionID` is available, embed a short identifier: `"Slice {shortID} complete ✓"`
  - `shortID` = first 8 chars of sessionID
- Truncate to 40 chars via `truncateToastMessage()`

**toastMessageForStepFailed(event: EventSessionNextStepFailed): string**
- Format: `"Step failed: {error.message}"`
- Truncate error message so total ≤ 40 chars
- If `event.properties.error` is undefined/null, fallback to `"Step failed"`
- Use `truncateToastMessage()` for final length enforcement

**toastMessageForServerConnected(_event: EventServerConnected): string**
- Returns exact copy: `"Auth token refreshed"` (per copywriting contract)

**toastMessageForSessionError(event: EventSessionError): string**
- Format: `"{errorType}: {shortMessage}"` — extract from `event.properties.error`
- If error has `.name` (e.g., `"ProviderAuthError"`), use it as prefix
- Truncate to 40 chars

**toastVariantForEvent(eventType: string): "info" | "success" | "warning" | "error"**

```typescript
  }
}
```

**toastDurationForEvent(eventType: string): number**
```typescript
function toastDurationForEvent(eventType: string): number {
  switch (eventType) {
    case "session.next.step.ended":   return 4000;   // success — brief
    case "server.connected":          return 4000;   // info — brief
    case "session.next.step.failed":  return 6000;   // warning — longer
    case "session.next.retried":      return 6000;   // warning — longer
    case "session.error":             return 0;      // error — persistent (opencode keeps visible)
    default:                          return 4000;
  }
}
```

**truncateToastMessage(message: string, maxLen = 40): string**
- If `message.length <= maxLen`, return as-is
- Otherwise: `message.slice(0, maxLen - 1) + "\u2026"` (single ellipsis char, matching UI-SPEC)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon SSE → toast state | Untrusted event data crosses from daemon process into toast dispatch |
| toast message → terminal display | User-visible message constructed from event data (potential injection) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-085-01 | Tampering | `toast.ts` — event message fields | mitigate | All message construction uses event property access with null guards. `toastMessageForStepFailed()` checks `event.properties.error` is defined before accessing `.message`. `truncateToastMessage()` enforces 40-char max, preventing oversized payloads from overflowing toast display. |
| T-085-02 | Denial of Service | `toast.ts` — de-duplication | mitigate | `shouldSuppressToast()` debounces identical messages within 10s. `recordToast()` prunes stale entries on every dispatch. Without de-dup, rapid-fire SSE events (e.g., retry loops) could flood the toast system and degrade terminal responsiveness. |
| T-085-03 | Information Disclosure | `toast.ts` — toast message content | accept | Toast messages display session identifiers (shortID, first 8 chars) and error messages. Session IDs are already visible in opencode UI via other mechanisms. Error messages are provider-facing, not user secrets. No PII or credentials in toast payloads. |
| T-085-04 | Elevation of Privilege | `toast.ts` — api.ui.toast() call | accept | `api.ui.toast()` is the sanctioned opencode API for showing toasts — no privilege boundary crossed. The plugin cannot invoke system dialogs or escape the terminal TUI sandbox. |
</threat_model>
