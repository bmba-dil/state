<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test file → module-level mutable state | Tests mutate exported const objects (BUILD_PROGRESS_STATE, etc.). Cross-test pollution risk in single-process bun execution. |
| Mock API fidelity | Integration test mocks TuiPluginApi methods. If mock diverges from real opencode API, tests pass but production fails. |
| File I/O in test context | SidebarContentRenderer and Statusline call `readFileSync(".state/mode.json")` — test environment may not have this file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-088-01 | Tampering | Module-level `const` state objects | mitigate | Every test resets state to factory defaults at start of `it()` block. No test relies on state left by previous test. |
| T-088-02 | Spoofing | Mock `TuiPluginApi` in integration test | mitigate | Mock objects mirror the real opencode API type signatures from `@opencode-ai/plugin/tui`. TypeScript compilation (`tsc --noEmit`) verifies mock shape matches declared types. |
| T-088-03 | Information Disclosure | Coverage report output | accept | Coverage data is local-only, no PII. Coverage percentages are aggregated — no individual file content exposed. |
| T-088-04 | Denial of Service | `readFileSync` in test execution | mitigate | Tests that depend on `.state/mode.json` via `SidebarContentRenderer` or `renderStatusline` are scoped to unit tests of pure functions only. Integration test uses mocks to bypass file I/O. |
| T-088-05 | Elevation of Privilege | `bun:test` mock() substitution | accept | bun test runs in isolated test environment with no production data. Mock substitution is the intended behavior of the test framework. |
</threat_model>
