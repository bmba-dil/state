<objective>
Create a mode-aware renderer for the `sidebar_content` TUI slot. Reads `.state/mode.json` at component mount via SolidJS `createResource` and conditionally renders one of four states: loading (while reading), empty (mode resolved, no session), active (placeholder stubs for Phase 082/083), or error (read failure). Includes a mode indicator row (Nerd Font icon + uppercase label) and content divider above the state area.

Purpose: This is the first functional consumer of Phase 080's TUI slot registration. It makes the sidebar_content slot meaningful by showing the current mode and providing placeholder anchor points for Phase 082 (BuildProgress) and Phase 083 (TeachConcept) to swap in real implementations.

Output: `src/tui/sidebar-content-renderer.tsx` (SolidJS component), `src/tui/sidebar-content-renderer.test.ts` (unit tests), modified `src/tui.ts` (slot integration).
</objective>

    **Exports (3):**
    - `SidebarContentRenderer` — default export, the SolidJS component called by the slot handler
    - `resolveMode(raw)` — pure function: takes `ModeJson | null | undefined`, returns `{ mode: ResolvedMode, status: "loading" | "empty" | "active" | "error" }`
    - `ModeInfo` type — `{ mode: "build" | "teach" | "both" | "unknown"; status: "loading" | "empty" | "active" | "error" }`

    **Implementation structure:**

    1. **Mode resolution** — Use SolidJS `createResource` with an async fetcher that reads `.state/mode.json` from `process.cwd()` via Node.js `fs/promises readFile`. Parse JSON, validate `mode` field is one of `"build" | "teach" | "both"`. If the file is missing or parse fails, the resource enters error state. The component starts in loading state while the resource is pending.

    2. **Mode indicator row** — 1 cell tall, format: `{Nerd Font icon} {UPPERCASE MODE}` with 1-cell gap between icon and label. Nerd Font glyphs per UI-SPEC §Mode Indicator:
       - Build: `` (U+E615, nf-dev-codeigniter)
       - Teach: `` (U+E28C, nf-fa-graduation_cap)  
       - Both: `󰘨` (U+F0628, nf-md-sync)
       - Unknown: `○` (U+25CB)
       Use `@opentui/solid` `Text` component with `bold: true` for the label, `bold: false` for the icon. Color per mode (from theme tokens): Build→`accent` (#6366F1), Teach→`success` (#10B981), Both→`info` (#3B82F6), Unknown→`textMuted` (#64748B).

    3. **Divider** — 1 cell tall, 28 `─` characters (U+2500, box-drawing light horizontal). Rendered as a `Text` with color `border` (#334155). Separates mode indicator from content area below.

    4. **Loading state** (`status === "loading"`) — Single line: `Reading mode…`. Text styled as Body, `dim: true`, color `textMuted`, top-aligned with `lg` (4-cell) top padding. No spinner animation — the read is typically <200ms.

    5. **Empty state** (`status === "empty"`, mode resolved but no active session):
       - Build mode: Two lines — `No active build session.` then 1-cell gap then `Run /gsd:execute-phase to begin.` (dim: true)
       - Teach mode: Two lines — `No active concept.` then 1-cell gap then `Select a subject to begin learning.` (dim: true)
       - Both mode: Stack both build and teach empty messages with a gap between them
       - Unknown mode: Single line — `Mode not configured.` (dim: true)
       - All text: Body style, color `textMuted`, top-aligned with `lg` padding.

    6. **Active state** (`status === "active"`) — Render placeholder stubs for downstream phases:
       - Build mode: `BuildProgress` placeholder box — a bordered rectangle using box-drawing characters (U+250C ┌, U+2500 ─, U+2510 ┐, U+2502 │, U+2514 └, U+2518 ┘). Title: `BuildProgress`. Body: `(Phase 082 will render here)`. All text `textMuted` + `dim: true`.
       - Teach mode: `TeachConcept` placeholder box — same box-drawing border pattern. Title: `TeachConcept`. Body: `(Phase 083 will render here)`.
       - Both mode: Both placeholders stacked, `BuildProgress` above, 1-cell gap, then `TeachConcept` below.
       - Each placeholder: `lg` (4-cell) top padding from divider/content area top.

    7. **Error state** (`status === "error"`) — Three lines with `lg` top padding:
       - Line 1: `Cannot read mode configuration` — Body, `bold: true`, color `error`
       - Line 2: `state-daemon may not be running.` — Body, `dim: false`, color `text`
       - Line 3: `Run state-daemon start to resume.` — Body, `dim: true`, color `textMuted`
       - 1-cell gap between each line.

    **Truncation:** All text lines must be truncated at 28 characters (not 28 cells — 28 chars is the budget for 28-cell width) with U+2026 `…` appended. No wrapping.

    **Theme fallback:** The component accesses theme via the SolidJS context or a module-level import of theme.json values. If the theme is not available at runtime, use the hardcoded hex values from theme.json directly. Do NOT assume the @opencode-ai plugin theme API is available inside the slot renderer — the slot function may not receive the API object.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-081-01 | Spoofing | `resolveMode()` | mitigate | Validate `mode` field is exactly `"build"`, `"teach"`, or `"both"` — any other value maps to `"unknown"` status. TypeScript `ModeJson` type enforces shape at compile time. |
| T-081-02 | Tampering | `createResource` fetcher | accept | mode.json is a local file controlled by the state-daemon process running on the same machine. If an attacker can write to `.state/`, they already own the filesystem. No cryptographic verification needed. |
| T-081-03 | Information Disclosure | Error state rendering | mitigate | Error message shows "Cannot read mode configuration" with recovery hint — does NOT leak file path, raw error details, or stack traces to the UI. Internal error is logged but not rendered. |
| T-081-04 | Denial of Service | `createResource` fetcher | accept | Reading a small JSON file (<100 bytes) is not a DOS vector. No retry loop, no polling. |
| T-081-05 | Elevation of Privilege | Mode rendering | accept | The component only reads mode.json and renders UI — no mode switching, no write operations, no auth bypass possible through this render path. |
</threat_model>
