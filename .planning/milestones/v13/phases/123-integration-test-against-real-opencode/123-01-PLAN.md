**test_server_starts_and_lists_tools:**
```python
import asyncio
import sys
from mcp.client.stdio import stdio_client
from mcp.client.session import ClientSession

async def _run():
    server_params = StdioServerParameters(
        command=sys.executable,
        args=["-m", "state_teach.mcp"],
        env={**os.environ, "STATE_MODE": "teach"},
    )
    async with stdio_client(server_params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools_result = await session.list_tools()
            tools = tools_result.tools
            assert len(tools) == 14, f"Expected 14 tools via MCP protocol, got {len(tools)}"
            tool_names = {t.name for t in tools}
            for name in REQUIRED_TOOL_NAMES:
                assert name in tool_names, f"MCP protocol: missing tool {name}"

asyncio.run(_run())
```

IMPORTANT: If `StdioServerParameters` is not available in this version of the MCP SDK, use the lower-level `stdio_client` directly with `command` and `args`. Check what's available first: `from mcp.client.stdio import stdio_client; help(stdio_client)`.
If the subprocess transport approach proves too fragile (e.g., portability issues), fall back to a documented skip with `pytest.skip("MCP stdio transport requires opencode test infrastructure — Phase 114 precedent")` and add a NOTE comment explaining the deferral. The test must not be left failing.

Use `--mode=teach` env or ensure `.state/mode.json` is set to `teach` before spawning. The subprocess inherits the test's environment. Create a tmp_path-based `.state/mode.json` with `{"mode": "teach"}` and set `cwd` on the server params to the tmp_path.
