# Phase 010.1 Plan A: CLI Mode Validation Summary

**Typer callback validation for `--mode` on all three `events` commands (`tail`, `replay`, `export`) rejecting values outside `{build, teach, kernel}` via `BadParameter`**

## Accomplishments

- Added `_validate_mode()` Typer callback that checks `--mode` values against `VALID_MODES = {"build", "teach", "kernel"}`
- Updated all three command signatures (`tail`, `replay`, `export`) to use `callback=_validate_mode`
- Invalid modes now produce `typer.BadParameter` with exit code 2 instead of silently returning 0 rows
- All 26 existing CLI tests continue to pass

## Task Commits

## Files Created/Modified

- `src/state_cli/main.py` - Added `_validate_mode` callback function, `VALID_MODES` constant, and wired callback to all three `--mode` options

## Decisions Made

- Used a plain `set[str]` with `typing.Final` instead of importing the `Mode` Literal type from `schema.py` — the set is sufficient for runtime validation and avoids coupling the CLI layer to the schema module's type system
- Raised `typer.BadParameter` (exit code 2) rather than soft-failing — this matches Typer's convention for usage errors and makes invalid mode a hard error visible in CI pipelines
- Sorted mode names in the error message for deterministic display: `"build, kernel, teach"` rather than the insertion order of the set
