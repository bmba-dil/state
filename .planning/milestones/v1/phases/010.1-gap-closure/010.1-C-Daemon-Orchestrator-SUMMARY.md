## Decisions Made

- **Used `run_repair_now()` over `repair_aggregate_seqs()`:** The plan's code called `repair_aggregate_seqs()` directly, but this bypasses the `_repair_done` flag that prevents redundant lazy repair calls. The dedicated `run_repair_now()` method was designed specifically for daemon startup — it calls the same repair logic AND sets `_repair_done` so that subsequent reconciler operations through the same store instance don't trigger unnecessary duplicate repair sweeps.
- **Used `StartupReconciler` + `SyncEventMirror`:** The plan referenced a `Reconciler` class with `reconcile()` method that does not exist in the codebase. The actual API is `StartupReconciler(db=store, mirror=SyncEventMirror()).start()`, which performs immediate reconciliation and then starts the periodic background sweep loop — appropriate for daemon lifecycle.
- **SyncEventMirror constructed with default directory (`Path.cwd()`):** Appropriate for daemon context where cwd is the project root.
