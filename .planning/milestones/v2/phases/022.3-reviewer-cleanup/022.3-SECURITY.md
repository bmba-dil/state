# Phase 022.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.
>
> **Scope:** Internal hardening of `state_core.observability.redactor` (Phase 020 layer-2 secret-leak defense). No new external inputs, no new dependencies, no schema changes, no new persistence surfaces. Threat surface is bounded to behaviors of an existing security-critical module.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Process → stdout/stderr | Structlog renders event-dicts to JSON via root logger | Redacted log records (12-pattern regex set + 12-key context-aware redaction) |
| Caller code → `_walk_value` | Recursive walk of arbitrary log payload (dicts, lists, tuples, BaseException) | Pre-redaction event-dict (may contain secrets in keys/values until walk completes) |
| `install()` config → root logger | Daemon startup mutates stdlib root logger handlers + level | Logging configuration (no secrets crossing) |
| `assert_redactor_attached()` → handler chain | Synthetic canary record exercises the configured ProcessorFormatter | Canary string (`sk-ant-oat-canary-<uuid4>-XXXX...`) — non-secret by construction |

| T-022.3-02 | Tampering (regression) | `_PATTERNS` order discipline (redactor.py:117-127) | mitigate | `tests/test_redactor.py:859 test_pattern_order_specific_before_generic` asserts `index('sk-ant-oat-') < index('(?<!\w)sk-[A-Za-z0-9]{40,}')`. | T-022.3-03 | DoS / Bypass | `_walk_value` tuple branch (redactor.py:191-214) | mitigate | NamedTuple / tuple-subclass cascade: `cls._make(walked)` → `cls(*walked)` → `tuple(walked)` fallback. | T-022.3-06 | Information Disclosure (misdiagnosis) | `assert_redactor_attached()` Path 2 formatter loop (redactor.py:487-512) | mitigate | `formatter_count` counter + immediate `raise RedactorNotAttached("ProcessorFormatter on root logger raised on canary render: {type(exc).__name__}: {exc!r}.") from exc` on broken-formatter render. Pre-fix, a broken formatter was misdiagnosed as "no formatter found", causing operators to chase the wrong fix and potentially deploy without working redaction. | closed |

## Accepted Risks Log

| Risk ID | Threat Ref | Rationale | Accepted By | Date |
|---------|------------|-----------|-------------|------|
| AR-022.3-01 | T-022.3-05 | Operator-tunable log level (`install(level=…)`) lets deployers reduce log volume by raising the level. Records below the chosen level never reach the root logger and therefore never pass through the redactor — but this is also true of the unmodified Phase 020 code (which hard-coded DEBUG). The new parameter does not introduce a new risk; it gives operators control over an existing behavior. Default remains `logging.DEBUG` to preserve maximum redactor coverage. | Thomas | 2026-05-02 |
