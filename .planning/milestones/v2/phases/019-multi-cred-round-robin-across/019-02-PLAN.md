<threat_model>
Wave 2 introduces a new exception type and promotes a private helper to public. Threats:

- **T-019-3 (HIGH→MEDIUM after mitigation):** `NoCredentialsAvailableError` exception message could leak credential bytes if `repr(cred)` ever appears in the message. Mitigation: the exception class accepts only `provider_id: str`, `reason: str` (constrained to `"empty"` | `"all_cooled_down"`), and `earliest_available_at: float | None`. The `__init__` MUST NOT accept any credential / vault arguments. The `__str__` / message format is `f"No credential available for {provider_id!r} (reason={reason})"` — the `!r` is on `provider_id` (a public string), never on `cred`. ASVS V8.3.1, V7.4.1.

- **T-019-W2-1 (LOW):** Promoting `_new_async_lock` to public surface (`new_async_lock`) could be misused by a non-rotation caller that forgets the `try/finally lockfile.touch` pattern (Phase 013's filelock 3.29 behavior). Mitigation: docstring on the public alias MUST reproduce the warning. Already-existing private callers (Phase 013 `read_credential` and `refresh_credential`) keep their `_lock_path_for(...).touch` pattern unchanged.

- **T-019-W2-2 (LOW):** Cycle risk — adding `NoCredentialsAvailableError` to `errors.py` MUST NOT introduce any state_core.auth.* imports at the errors.py module scope (errors.py is the foundation; cycles forbidden per Phase 011 cardinal rule). Mitigation: errors.py keeps its `imports limited to stdlib only` invariant. No change to imports.

- **T-019-W2-3 (LOW):** Backward compat — Phase 013 internals (refresh.py) still use `_new_async_lock` as a private name. Promoting to public adds `new_async_lock = _new_async_lock` (or moves the def + adds underscored alias) — both must continue working. Mitigation: keep `_new_async_lock` as the canonical name (zero-edit Phase 013 internals); add `new_async_lock = _new_async_lock` as a public alias and append `"new_async_lock"` to `__all__`.

Severity: highest is T-019-3 with controlled mitigation (constructor signature alone enforces it). No HIGH residual.
</threat_model>
