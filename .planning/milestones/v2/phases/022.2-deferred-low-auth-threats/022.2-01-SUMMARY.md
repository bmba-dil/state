## Decisions Made

- **Reload-resilience helper instead of altering STORE-17:** Rather than refactor STORE-17 (`test_no_mode_imports`) to restore module state after its `importlib.reload`, each STORE-22 test resolves its surface fresh from `sys.modules` via a small `_store()` helper. This stays minimum-touch on existing tests and documents a reusable pattern for any future reload-affected test.
- **`Path.is_symlink()` over `stat.S_ISLNK(os.lstat(path).st_mode)` in `ensure_initialized`** for readability; functionally equivalent (Path.is_symlink uses os.lstat internally).
- **Cross-platform symlink check on the Windows branch of `_verify_mode`:** symlinks exist on Windows (mklink /D, mklink /H) and `os.lstat` is valid there. Mode-bit comparison still skipped on Windows per the existing pre-Phase-022.2 policy.
- **No `os.readlink` in the exception message:** the link target could itself be a sensitive path (e.g. under `~/Documents/secrets/`); we surface only the offending vault-side path.
- **No auto-chmod, no auto-delete on symlink detection:** preserves the no-auto-fix policy that already governs `AuthVaultPermissionError` (STORE-12).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] STORE-22 tests were broken by STORE-17's module reload**
- **Found during:** Task 2 (initial run after writing the six STORE-22 tests)
- **Issue:** The first draft of the STORE-22 tests imported `AuthVaultSymlinkError` at module top. STORE-17 (`test_no_mode_imports`) calls `importlib.reload(state_core.auth.store)` halfway through the file's test order, which makes the test-file-level reference a stale class object. After reload, `_verify_mode` etc. raise the *new* module's `AuthVaultSymlinkError`, which `pytest.raises(...)` then doesn't catch (different identity). Result: the four functional STORE-22 tests failed with the exception visible in the traceback but `pytest.raises` not matching. The two non-functional tests (STORE-22e message hygiene, STORE-22f positive control) passed because they don't depend on identity matching across a reload.
- **Fix:** Introduced a small `_store()` helper that does `importlib.import_module("state_core.auth.store")` at call time. Each STORE-22 test now resolves `AuthVaultSymlinkError`, `_verify_mode`, `_atomic_write`, `load_vault`, `ensure_initialized`, `save_vault`, `AuthVault`, and `TMP_SUFFIX` via `s = _store()` rather than via the file-level imports.
- **Files modified:** `tests/auth/test_store.py`
- **Verification:** `pytest tests/auth/test_store.py -q` → 27 passed (was 4 failed + 23 passed before the fix).
- **Committed in:** `70fa1f8` (Task 2 commit; the fix landed as part of the same task before the commit was created).
- **Why Rule 1 (bug) and not Rule 4 (architectural):** The fix is a 1-line-per-test refactor inside the new tests. It does not alter STORE-17's behaviour, does not change the production module, and does not break any other test.

**Total deviations:** 1 auto-fixed (Rule 1 bug in test design).
**Impact on plan:** No scope change. All other plan steps executed exactly as written. The `_store()` helper also documents a reusable pattern for any future reload-affected test.
