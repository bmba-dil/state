<objective>
Close T-018-9 (symlink-attack mitigation on `auth.json`).

The current `state_core.auth.store` module opens its atomic tmp file with `os.O_WRONLY | os.O_CREAT | os.O_TRUNC` (NO `O_NOFOLLOW`) and uses `os.stat` (which silently follows symlinks) for mode verification. This means a local attacker who can plant a symlink at `.state/auth.json` (or `.state/auth.json.tmp`) before the daemon runs can: (a) redirect the write to an attacker-controlled location with attacker-controlled mode, or (b) cause `_verify_mode` to validate the *target's* mode while the link itself remains a 0o777 attack vector.

Phase 018-RESEARCH (T-018-9) and Phase 012-RESEARCH both flag this as a deferred LOW threat. The skipped placeholder test `test_symlink_attack_rejected` (tests/auth/test_store.py:473-480) marks the gap. Phase 022.2 closes it.

Purpose: Restore POSIX-standard symlink-attack defense to the vault layer; flip the OUT-OF-SCOPE docstring claim to CLOSED; turn the skipped placeholder into a real, passing assertion.

Output: Hardened `store.py` (new `AuthVaultSymlinkError` exception, `O_NOFOLLOW` flag, `os.lstat` switch) + 4+ new/upgraded tests in `test_store.py`.
</objective>

<threat_model>
| ID | Severity | Threat | Mitigation in this plan |
|----|----------|--------|--------------------------|
| T-018-9 | LOW | Symlink at `auth.json` or `auth.json.tmp` redirects writes / leaks reads | (1) `os.O_NOFOLLOW` added to `_atomic_write`'s `os.open` flags; ELOOP errno re-raised as `AuthVaultSymlinkError`. (2) `_verify_mode` switched from `os.stat` to `os.lstat`; raises `AuthVaultSymlinkError` if `S_ISLNK(mode)` on the path itself. Severity rationale: LOW because attacker needs local FS access in `.state/` directory (single-user POSIX vault). Mitigations are POSIX-standard (`O_NOFOLLOW` is in POSIX.1-2008; `os.lstat` is in stdlib since Python 1.x). No behavior change in the happy-path (regular file at vault path → no errno difference).
</threat_model>

        ...
        Also raises AuthVaultSymlinkError if *path* itself is a symlink (T-018-9).

                log.warning(...)  # unchanged
                _WINDOWS_WARNING_EMITTED = True

            if stat.S_ISLNK(st.st_mode):
                raise AuthVaultSymlinkError(path)
