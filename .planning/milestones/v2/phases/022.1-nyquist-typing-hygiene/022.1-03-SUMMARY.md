## Issues Encountered

### mypy module-resolution friction (worked around, not fixed)

When invoked as `python3 -m mypy src/state_core/` from the repo root, mypy reported:

```
src/state_core/auth/base.py: error: Source file found twice under different module names: "src.state_core.auth.base" and "state_core.auth.base"
Found 1 error in 1 file (errors prevented further checking)
```

This is a `src/`-layout module-path ambiguity unrelated to py.typed. **Resolved at invocation time** by running `cd src/ && python3 -m mypy -p state_core` instead. The smoke check completed successfully under the alternative invocation.

**Recommendation for future cleanup phases:** Add either an `__init__.py` in `src/` (turning it into a namespace) or a `mypy.ini` / `pyproject.toml` `[tool.mypy]` config with `mypy_path = "src"` and explicit package roots. Out of scope for 022.1.

### Pre-existing mypy errors (recorded for future cleanup, NOT fixed)

Running mypy on `state_core` (with the workaround above) surfaced **30 pre-existing typing errors in 13 files**. These are unrelated to py.typed and out of scope per the plan's explicit guidance ("Do NOT attempt to fix any unrelated mypy errors uncovered by this run").

Categorized breakdown for future cleanup phases:

- **`[import-not-found]` (8 occurrences)** — `src.state_core.*` paths inside `projector.py`, `migrations.py`, `events.py`, `sync_mirror.py`. Caused by inconsistent absolute vs. src-relative imports inside the package. Fix: replace `src.state_core.*` imports with `state_core.*`.
- **`[type-arg]` (5 occurrences)** — Missing generic args (`dict`, `frozenset`) in `state_core/auth/providers/{anthropic,google_gemini,antigravity}.py` and `projector.py`.
- **`[valid-type]` (3 occurrences)** — `_HandlerFn` variable used as a type annotation in `projector.py`. Should be `TypeAlias` or moved into `typing.TYPE_CHECKING`.
- **`[arg-type]` / `[union-attr]` (4 occurrences)** — Union-narrowing issues in `state_core/auth/providers/api_key.py` and `cli_ops.py`.
- **`[assignment]` (2 occurrences)** — Type widening in `projector.py` and `cli_ops.py`.
- **`[no-any-return]` (1 occurrence)** — `migrations.py:23` returns `Any` declared as `Path`.
- **`[unused-ignore]` (1 occurrence)** — `cli_ops.py:415`.

Critically, **zero `[import-untyped]` warnings** appeared in the entire mypy run, confirming the py.typed marker is working as intended for state_core.
