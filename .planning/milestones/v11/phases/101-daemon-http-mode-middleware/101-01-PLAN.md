<objective>
Extend the daemon's ModeMiddleware (the canonical mode gate, layer 5 of 6) to inspect the event type inside JSON-RPC request bodies and reject teach-mode events (`state.concept.*`, `state.drill.*`) when the active mode is "build", and reject build-mode events (`state.arc.*`, `state.phase.*`, `state.slice.*`, `state.step.*`) when the active mode is "teach".

Purpose: Strengthen mode-isolation defense-in-depth — the existing middleware validates the `X-State-Mode` header (coarse: "which mode is the caller claiming?"), but not the actual event payload. This extension adds payload-level validation: even if the header says "build", a `state.concept.introduced` event is blocked. This prevents bugs where a worker or plugin sends the wrong event type through a correctly-moded channel.

Output: Updated `ModeMiddleware.__call__` with event-type gating; `TEACH_ONLY_EVENT_PREFIXES` / `BUILD_ONLY_EVENT_PREFIXES` frozen sets in `schema.py`; comprehensive tests covering all rejection scenarios.
</objective>

```python
def _extract_event_type(body: bytes) -> str | None:
    """Extract the event type from a JSON-RPC ``state.emit`` request body.

    Parses the JSON body to find ``params.type`` when the method is
    ``"state.emit"``.  Returns ``None`` for any other method, malformed
    JSON, or missing type field — the caller decides how to handle.

    Args:
        body: Raw HTTP request body bytes.

    Returns:
        The event type string (e.g. ``"state.concept.introduced"``),
        or ``None`` if extraction is not applicable.
    """
    try:
        payload = json.loads(body)
    except (json.JSONDecodeError, TypeError):
        return None

    if not isinstance(payload, dict):
        return None

    if payload.get("method") != "state.emit":
        return None

    params = payload.get("params")
    if not isinstance(params, dict):
        return None

    return params.get("type", "")
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker/plugin → Daemon HTTP | Untrusted event payloads cross from worker/plugin into daemon via unix socket |
| JSON-RPC body → ModeMiddleware | Event type extracted from JSON-RPC params.type — input is attacker-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-101-01 | Spoofing | `ModeMiddleware.__call__` | mitigate | Attacker with valid build-mode header sends `state.concept.introduced` — rejected at event-type gate (event_type starts with teach-only prefix → 403). Defense-in-depth: even if header auth is bypassed, event payload is validated. |
| T-101-02 | Tampering | `_extract_event_type()` | mitigate | Malformed JSON, missing params, wrong types — all return `None` (skip check) or `""` (empty string passes through without rejection). The defaul is permissive on malformed input — the router handles its own validation. No crash, no surprise rejection. |
| T-101-03 | Information Disclosure | `_reject()` rejection payload | accept | Rejection payload includes `event_type` in 403 response body. Low-value target — the daemon socket runs on a local unix socket (0600 permissions). Event type names are public knowledge (defined in open-source schema.py). |
| T-101-04 | Elevation of Privilege | `ModeMiddleware.__call__` kernel bypass | accept | Kernel request mode bypasses event-type checks — this is intentional. Kernel mode is internal-only (not exposed to workers/plugins) and is used for daemon-internal operations like auth refresh and event replay. If an attacker can spoof kernel mode, they have already compromised the local machine. |
</threat_model>
