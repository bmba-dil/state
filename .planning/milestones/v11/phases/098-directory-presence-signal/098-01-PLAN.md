     ```python
     def validate_subtree_path(path: str | Path, mode: str) -> None:
         """Validate that *path* is within the allowed subtree for *mode*.
     
         When *mode* is ``"build"``, the path must NOT start with ``.state/teach``.
         When *mode* is ``"teach"``, the path must NOT start with ``.state/build``.
         When *mode* is ``"both"``, all paths are allowed.
     
         Paths in the ``.state/`` root (e.g. ``.state/mode.json``,
         ``.state/events.sqlite``) are always allowed — they are shared
         kernel-level files, not mode-specific.
     
         Args:
             path: A filesystem path (string or ``pathlib.Path``).
             mode: The active mode (``"build"``, ``"teach"``, or ``"both"``).
     
         Raises:
             ValueError: If *mode* is unrecognised or *path* crosses into
                         the wrong subtree.
         """
         # Implementation: convert path to string via str(), strip leading ./,
         # normalize to posix, then check prefix. Logic:
         #   - mode == "both" → return (no restriction)
         #   - path_str.startswith(".state/") but NOT ".state/build/" and NOT ".state/teach/" → return (shared root)
         #   - mode == "build" and path_str.startswith(".state/teach/") → raise ValueError
         #   - mode == "teach" and path_str.startswith(".state/build/") → raise ValueError
         #   - Edge: path_str == ".state/build" (exact, no trailing /) → treat as ".state/build/"
         #   - Edge: unrecognised mode → raise ValueError
         # Use pathlib.Path normalization: str(Path(path)).replace(os.sep, "/")
         # then re-add ".state/" prefix if it was present in the input
     ```
     The executor should implement the normalization logic. Key invariant: a path like

     `.state/teach/subdir/file.json` is rejected for mode=build. The shared root
     (`.state/mode.json`, `.state/events.sqlite`) is never rejected by this function
     regardless of mode.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI invocation → filesystem | The CLI writes to `.state/`; untrusted mode arguments cross here |
| filesystem → daemon | The daemon reads `.state/` structure as an enforcement signal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-098-01 | Tampering | mode_init CLI | mitigate | `validate_mode_config()` (Phase 097) rejects invalid mode strings before any filesystem write — cannot create subtrees for invalid modes |
| T-098-02 | Tampering | schema.py constants | mitigate | Constants are module-level, immutable strings — no runtime mutation path |
| T-098-03 | Information Disclosure | subtree directory creation | accept | Directories are empty (no content to leak); 0755 default perms are acceptable for directory-only structure |
| T-098-04 | Elevation of Privilege | mode_init both-mode | mitigate | Both-mode is the documented "dual-mode project" config — allowed by design per ModeConfig Literal constraint |
</threat_model>
