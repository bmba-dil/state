       global _event_store
       if _event_store is None:
           log.warning("daemon.mode_event.no_store")

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI → Daemon (SIGHUP) | Signal sent from `state mode set` CLI to daemon process |
| Daemon → Event Store (SQLite) | Domain event written to authoritative store |
| Event Store → SSE Bus | Post-commit callback fans out to SSE subscribers |
| SSE → Plugin (HTTP) | Event streamed to opencode plugin over HTTP+SSE |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-01 | Tampering | `_schedule_mode_reload` signal handler | mitigate | Only process SIGHUP from own process (signal can only be sent by same-user process on Unix). Untrusted mode.json values rejected by `load_mode_config()` pydantic validation before event emission. |
| T-104-02 | Information Disclosure | `state.mode.activated` event payload | accept | event contains only mode strings (build/teach/both) — no secrets, tokens, or PII. Low-risk. |
| T-104-03 | Elevation of Privilege | Mode event emission | mitigate | Event emitted with `mode="kernel"` so it passes through all middleware gates regardless of active mode. Cross-mode attack neutralized — kernel events cannot trigger domain-specific handlers. |
| T-104-04 | Denial of Service | SSE fan-out on every mode change | accept | Mode changes are infrequent (manual CLI operations). No amplification vector. Event store append is lightweight (~KB). |
</threat_model>
