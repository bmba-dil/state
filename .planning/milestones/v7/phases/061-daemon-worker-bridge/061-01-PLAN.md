# Plan 061-01: Daemon ↔ Worker Bridge (HTTP+SSE Client)

**Goal:** Implement the worker bridge module that subscribes to the daemon SSE event stream and provides event callbacks.

**Requirements:** WRK-10, WRK-12

### Tasks

#### 061.1 — SSE client bridge (parsing + connection)
**Acceptance:** Bridge can connect to daemon SSE endpoint, parse event stream lines, and dispatch parsed events
**Estimated effort:** Medium
**Dependencies:** 060.2
**Details:**
- Implement `src/state_worker/bridge.py` with `SseBridge` class
- `connect(socket_path, session, mode_filter)`: opens Unix socket, sends GET /events/subscribe HTTP request, enters read loop
- Parse SSE lines: `id: <ULID>`, `data: <JSON>`, `event: <type>`, blank line as boundary
- `on_event` attribute: Awaitable callback receiving parsed SSE events
- Heartbeat detection: skip empty `data:` lines (keepalive)
- Connection error handling with reconnection callback

- src/state_worker/session.py (SessionIdentity)
</read_first>

<action>
Implement `src/state_worker/bridge.py`:
- `SseBridge` class:
  - `__init__(self, session: SessionIdentity, mode_filter: str | None = None)`
  - `on_event: Callable[[dict[str, object]], Awaitable[None]] | None` — callback for parsed SSE events
  - `async connect(self, socket_path: str) -> None` — open Unix socket, send GET /events/subscribe request with query params, read SSE lines in a loop
  - `async disconnect(self) -> None` — close socket
  - `_running: asyncio.Event` — signals the read loop to exit
- Parse SSE lines per spec:
  - Lines ending with `\n` or `\r\n`
  - `id:` sets the event ID
  - `data:` accumulates data (multi-line `\n` joined)
  - `event:` sets the event type
  - Empty line triggers dispatch of accumulated event
- Skip heartbeats (events with no `data` field)
- Log connection/disconnection/errors via structlog
</action>
